# Candidate input contract

The host Agent must write UTF-8 JSON. The Python CLI does not call a model and cannot generate candidates from `topic` alone. Candidate data belongs in the user's input file, never in an embedded domain database.

Top-level: `topic` nonempty string; optional `focus`/`exclude` string lists, `count` 1–200 (default 50), `language` `bilingual|english|chinese`, `mode` `quick|research`, `depth` `narrow|balanced|broad`, `cross_domain` and `search_queries` booleans, `output_format` `markdown|json|csv|all` (default markdown), `domain_analysis` object, `search_concepts` array, `relationships` array, optional `report_date` in YYYY-MM-DD for reproducible reports, and required `candidates` array. `verify_terms` may be true only with research mode. Optional fields include `task_strategy` (`field_overview|research_problem|method_exploration|literature_search`), `evaluate_queries` boolean (default true in Research Mode), `query_revision_rounds` 0–2 (default 2), `previous_report` object, and `revision_reason` string. A reviewer can optionally supply `query_relevance_labels` (DOI/URL → Boolean) and `query_label_source` (`human_review|agent_review`); only human-labelled sampled rows produce a labelled-sample precision estimate.

Each candidate requires `keyword` (canonical English phrase), `chinese` (blank only if translation is uncertain; explain in reason), `category` (field-specific), `term_type` (`standard|related|exploratory`), `reason`, and `scores`. The score object has exactly `direct_relevance`, `term_accuracy`, `coverage_potential`, `cross_domain_value`, `distinctiveness`, each integer 0–100. Optional: `abbreviation`, `synonyms` list, `scope` (`core|adjacent|transfer`, default core), `query_role` (`problem|method|application`, default problem), `layer` (`core_concept|theory|method|subproblem|metric|adjacent|transfer`), `focus_tags` list, `score_reason`, and `concept_id` (same value only for truly equivalent expressions). Candidates can also provide independent `topic_relevance`, `search_utility`, and `exploration_value` (`high|medium|low`), `term_class` (`established_term|general_academic_term|descriptive_phrase|exploratory_term`), `translation_note`, and optional `verification_review`. Missing levels are transparently derived from the five numeric scores. A supplied `term_class` is an Agent estimate until corroborated.

Search concepts are `{id, role, terms}` with role `research_object|research_problem|method|application_context|theory|adjacent_domain`. Terms within one group must describe the same concept. Relationships are `{source, target, relation, explanation, semantic_status}`. New relation types are `is_a|part_of|uses_method|models|evaluated_by|related_to|potential_transfer`; legacy types remain accepted with a migration warning. Both endpoints must be retained keyword names to appear in the report. Missing nodes, duplicates, and some possible direction errors are reported. `semantic_status` does not claim literature verification; read [relationship rules](relationship-rules.md).

`verification_review`, if provided for a Research Mode candidate, is `{status, reason, evidence_url, reviewer?}`. Status is `context_supported` or `expert_reviewed`; expert review requires `reviewer`. The cited URL or DOI must match a record retrieved in that run. Otherwise Python keeps the lower evidence state and emits a warning. Run once to collect metadata, review the record, then rerun with the review attached. Do not fill this field merely because a phrase appears in a title.

Keep `concept_id` stable only within this request. For example, full name and abbreviation may share one ID, while optical proximity correction and inverse lithography must not. A phrase pair that merely shares words belongs to separate concepts. Mark proposed cross-field techniques as scope `transfer` and type `exploratory` unless their name is a standard term in its own source field; the relation to the target application still remains unverified.
